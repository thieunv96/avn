# Spec: avn v2.13, năm thay đổi cho baseline

- Ngày: 2026-11-27. Trạng thái: đã triển khai trên nhánh `feat/v2.13.0` (chưa commit); còn checklist
  trong phiên tương tác do người dùng thử, xem mục End-to-end check.
- Nguồn: 6 vòng phỏng vấn; đo transcript (nhật ký phiên Claude Code) của khoảng 28.000 lần gọi
  tool trong 5 project, tháng 10–11/2026; tài liệu Claude Code 2.1.332.
- Số thứ tự vấn đề giữ theo danh sách gốc của người dùng. Vấn đề 5 (tách lĩnh vực AI và web) đã
  được bỏ khỏi bản này, xem mục Out of scope.

## Problem

|---|---|---|---|
| 1 | Báo cáo dài, sai trọng tâm, xấu | Baseline không có quy trình hay mẫu báo cáo | Phỏng vấn |

| 3 | Claude tự dùng thư mục ngoài | Không có ranh giới nào theo thư mục | 11.087 lần file tool đọc NAS; khoảng 80 lệnh vào project khác; khoảng 3.200 lần ghi vào `/tmp`; gần như không lần nào hỏi |

Phát hiện kèm theo: các phiên chạy ở `auto` và `plan` mode, không phải `acceptEdits` như README và
`CLAUDE.md` §5 mô tả. Ở `auto` mode, Claude Code bỏ qua rule `allow: Bash` trần của avn và để
classifier duyệt lệnh. Vì vậy mọi thay đổi dưới đây chỉ dựa vào rule `ask`, rule `deny` và hook,
là ba thứ chạy giống nhau ở mọi mode.

## Goal

- Báo cáo ra đúng hai bản (tóm tắt và chi tiết), trực quan, theo một bộ quy tắc cố định.
- avn chỉ hỏi quyền khi lệnh thay đổi hoặc xóa dữ liệu.
- Mọi truy cập ngoài thư mục phiên phải được người dùng cấp bằng `/add-dir`, mỗi thư mục một lần
  mỗi phiên.
- Không còn đường nào để phiên làm việc trong worktree.
- Mọi câu trả lời giải thích thuật ngữ theo đúng trình độ và cách đọc của người dùng.

## Files & interfaces involved

Một lệnh của Claude đi qua các lớp sau:

```
Lệnh của Claude
      |
      v
[1] Hook của avn (bash-guard, scope-guard) -- chặn --> Claude đưa lệnh cho người dùng tự chạy,
      | qua                                           hoặc nhờ người dùng gõ /add-dir
      v
[2] Rule deny / ask trong settings ---------- ask ---> hộp hỏi Yes/No
      | qua
      v
[3] Setting chặn ngoài thư mục phiên ------- ngoài --> từ chối, cần /add-dir
      | trong
      v
[4] Mode (auto: classifier, acceptEdits: allow) -----> chạy
```

| Thay đổi | File | Việc cần làm |
|---|---|---|
| 1. Báo cáo | `src/skills/report/SKILL.md` (mới) | Một file liệt kê quy trình và quy tắc: xác định người đọc và mục tiêu, gom số liệu thành file dữ liệu, chọn loại hình theo dữ liệu, xuất hai bản, tự kiểm theo checklist. Không có mẫu HTML, không có code vẽ biểu đồ |
| 2. Hỏi quyền | `src/settings.json`, `src/settings.relaxed.json` | Bỏ rule `ask` theo tên công cụ cho docker, aws, psql, mysql, redis-cli, systemctl, gcloud, az, kubectl, helm; thêm rule `ask` theo hành động thay đổi dữ liệu. Profile relaxed vẫn không hỏi docker và DB CLI như hiện nay |
| | `src/hooks/bash-guard.sh` | Thông báo chặn thống nhất: "đưa nguyên lệnh cho người dùng chạy" |

| 3. Thư mục | `src/settings*.json` | Bật `blockReadsOutsideWorkingDirectories` và `blockWritesOutsideWorkingDirectories`; nối hook mới vào `PreToolUse` (Bash) và `DirectoryAdded` |
| | `src/hooks/scope-guard.sh` (mới) | Chặn đường dẫn ngoài trong lệnh Bash; ghi nhận thư mục đã `/add-dir` theo từng phiên, lưu trong `~/.claude` |

## Out of scope

- Vấn đề 5, tách lĩnh vực AI và web/app: bỏ theo quyết định ngày 2026-11-27. `CLAUDE.md` §9, §10,
  `rules/testing.md` và `rules/realtime-performance.md` giữ nguyên, nên việc áp nhầm rule giữa hai
  lĩnh vực vẫn có thể xảy ra.
- File `~/.claude/settings.json`: giữ nguyên theo quyết định của người dùng.
- Phần tổng kết cuối task trong chat (`## Summary / Changed / Verified`): không đổi.
- Sandbox của Claude Code: chưa dùng, vì tài liệu ghi không tương thích với docker và còn lỗi mở
  với GPU và NFS.
- Lưu quyền thư mục qua nhiều phiên: không làm; mỗi phiên cấp lại.
- Mẫu HTML cố định, code vẽ biểu đồ, thư viện biểu đồ: không làm; skill `report` chỉ liệt kê quy tắc.
- Xếp loại lệnh trong hook để chặn lệnh chưa rõ loại: không làm; mode quyết định.
- Giữ script thử `claude -p` trong repo: không làm; script chỉ nằm trong `build/e2e/`.

## End-to-end check (how we prove it works)

1. Chạy 7 bộ test (6 hiện có, 1 mới cho `scope-guard`); tất cả phải qua.
2. Cài bản mới vào `build/e2e/fixture` (thư mục đã gitignore, nằm trong repo avn) và chạy thử từng
   tình huống bằng `claude -p` ở `acceptEdits` và ở `auto` mode, đọc kết quả từ
   `--output-format stream-json`. Lệnh thử phải vô hại kể cả khi lớp chặn hỏng. Phần chỉ thấy khi
   tương tác (gõ `/add-dir`, hộp hỏi Yes/No, giao diện báo cáo) do người dùng thử theo checklist.
   Riêng 2.1 đến 2.3 trong phiên tương tác chỉ thấy khác biệt khi file cấp user không còn rule `ask`
   theo tên công cụ.
3. Sau một tuần dùng thật, chạy lại script đo transcript và so với số liệu ở Phụ lục.

    đó là cách code dùng kubeconfig thật; script `awk`/`jq` và mẫu nằm trong `$(...)` vẫn bị quét.
  - Sau lượt review thứ hai, phần đọc lệnh của `bash-guard` (rule 3, 14, 15) và `scope-guard` được
    viết lại quanh một bộ đọc lệnh chung. Đối chiếu trên 497 lệnh: 46 lệnh bản cũ chặn mà bản mới
    cho qua, đều là lệnh đọc hoặc chữ thuần; bộ đọc khớp bash thật trên 49 kiểu quote và 32 cấu
    trúc lệnh. Thêm ngoài phạm vi ban đầu: sau `cd .claude` mọi lệnh sửa file phía sau bị chặn.
  - Kết quả thử phiên thật trên bản cuối (2026-11-27, `claude -p`, model Opus): 29/29 tình huống ở
    `acceptEdits`, 5/5 ở `auto` mode, 3/3 phép thử đối chứng; tool `EnterWorktree` và `ExitWorktree`
    không còn trong phiên; `Read` ngoài dự án bị từ chối; `/report` tạo đủ `summary.html`,
    `report.md`, `data/*.csv` và trang HTML không tải gì từ mạng.
  - Dữ liệu hook nhận được (đo bằng một hook ghi lại input): `session_id`, `cwd`, `transcript_path`,

    `hook_event_name`. Trường `scratchpad_dir` có trong tài liệu hook (Claude Code 2.1.257 trở

    session id trong đường dẫn mặc định.

    `Read` đọc được dù bật chặn đọc ngoài thư mục; `cat` bằng Bash bị `scope-guard` chặn, kèm lời

## Thuật ngữ

| Thuật ngữ | Nó là cái gì |
|---|---|
| hook | Script mà Claude Code tự chạy trước hoặc sau một sự kiện, ví dụ trước mỗi lệnh Bash; hook có thể chặn lệnh |
| rule `allow` / `ask` / `deny` | Dòng trong settings cho phép, bắt hỏi, hoặc cấm một lệnh khớp mẫu. `deny` thắng `ask`, `ask` thắng `allow`, ở bất kỳ file settings nào |
| `auto` mode | Chế độ quyền trong đó một bộ phân loại tự duyệt từng lệnh thay vì hỏi người dùng |
| classifier | Bộ phân loại tự động của `auto` mode, quyết định cho chạy hay chặn |
| `acceptEdits` | Chế độ quyền tự chấp nhận việc sửa file trong thư mục phiên |
| worktree | Bản sao thư mục làm việc thứ hai của cùng một repo git, nằm ở thư mục khác |
| scratchpad | Thư mục tạm riêng của từng phiên, do Claude Code tự tạo |
| `/add-dir` | Lệnh người dùng gõ trong phiên để cho Claude dùng thêm một thư mục, có hiệu lực đến hết phiên |
| skill | Bộ hướng dẫn đóng gói mà Claude nạp khi gặp đúng loại việc, gọi bằng `/tên` |
| file cấp user | `~/.claude/settings.json`, áp dụng cho mọi project trên máy |
